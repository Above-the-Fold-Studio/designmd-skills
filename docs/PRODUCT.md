# Product principles

## Purpose

Design Skills turns durable design practice into portable instructions that
help coding agents make better product decisions. It complements DesignMD, but
stands alone and can grow under its own public identity.

## V1 promise

V1 contains twelve narrow skills: six design foundations and six product-design
workflows. Each has a concise agent entrypoint, a useful human guide,
provenance, routing fixtures, and evidence appropriate to its quality status.

## Product boundary

The repository provides free, open skills and the metadata needed to discover,
install, understand, and test them. It does not require or bundle DesignMD
authentication, private catalogs, hosted certification, analytics, a custom
installer, an MCP server, a website, or telemetry.

These can be optional integrations or separate products. The standalone
workflow must remain complete when they are absent.

## Non-goals

- Becoming an unreviewed directory of every design prompt on GitHub.
- Republishing component libraries, visual assets, or paid instruction packs.
- Cloning another author's voice or removing attribution through paraphrase.
- Building a custom CLI or hosted catalog before the standard ecosystem proves
  insufficient.
- Using install counts as a substitute for usefulness.

## Free and paid boundary

Public skills remain free. DesignMD may charge for managed capabilities such as
private design-system retrieval, organization policies, version governance,
automated conformance, or visual validation at scale. Payment buys service and
infrastructure, not access to basic design knowledge.

## Decision test

A change belongs here when it makes a portable design skill easier to discover,
safer to trust, or more useful. It belongs in DesignMD when its primary value
depends on hosted data, accounts, entitlements, private context, or managed
execution.
