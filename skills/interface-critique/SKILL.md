# Interface Critique

Evaluate how well an existing interface supports its intended users and task.
Use this for a holistic critique of a page, flow, screenshot, prototype, or
implementation.

Do not replace evidence with taste. Do not redesign everything, praise without
analysis, or report a standards failure that was not actually tested.

## Workflow

1. Establish the user, job, surface, desired outcome, and available evidence.
   State missing context and bounded assumptions.
2. Walk the main path and realistic alternatives. Inspect hierarchy, content,
   navigation, controls, feedback, states, responsiveness, accessibility,
   consistency, and trust.
3. Record each finding as: observation, affected task or user, consequence,
   evidence, and recommended direction.
4. Distinguish defects from preferences. Tie defects to broken goals,
   established patterns, system rules, or measurable access and usability risk.
5. Prioritize blockers and irreversible loss first, then repeated friction,
   comprehension, consistency, and polish.
6. Preserve what already works. Recommend the smallest coherent set of changes
   rather than an unrelated visual reinvention.
7. Identify what needs live interaction, device, content, analytics, or user
   testing before it can be confirmed.

## Output

Lead with the overall diagnosis, then prioritized findings and a sequenced
improvement plan. Separate confirmed evidence, inference, and unverified tests.
