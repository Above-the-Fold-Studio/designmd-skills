# Visual Hierarchy

## Outcome

An interface whose importance can be understood before every word is read.

## Use it when

- Multiple cards, controls, or metrics compete equally.
- A primary action is visually weaker than secondary actions.
- Headings describe structure but do not look structurally different.
- Dense screens are technically organized but hard to scan.

## Principles

Hierarchy is relative. Making one item larger has little effect if five nearby
items are equally bold, saturated, and animated. First remove accidental
competition, then emphasize the true priority.

Use several aligned cues instead of relying on one: position plus whitespace,
or type scale plus weight. Preserve semantic heading order and keyboard focus;
visual order should clarify the information model rather than contradict it.

## Example request

> This dashboard feels flat. Make the next action and the account risk obvious
> without hiding the supporting metrics.

## Related skills

Typography, layout-and-spacing, and color-and-contrast refine individual
hierarchy tools. Interface-critique evaluates the whole experience.
