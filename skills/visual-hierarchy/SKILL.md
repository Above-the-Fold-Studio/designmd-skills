# Visual Hierarchy

Make importance visible. Use this when an interface feels flat, noisy,
mis-prioritized, difficult to scan, or unclear about what happens next.

Do not use decoration to compensate for weak content order. Do not make every
element louder, and do not change product priority without evidence.

## Workflow

1. Identify the primary user goal, the essential supporting information, and
   the action or decision the surface should make easiest.
2. Read the interface at a glance, then in detail. Note the actual first three
   attention targets and compare them with the intended order.
3. Diagnose competition across size, weight, contrast, position, whitespace,
   grouping, repetition, and motion.
4. Establish one dominant focal point per meaningful region. Reduce competing
   emphasis before adding more.
5. Group related items through proximity and alignment. Separate changes in
   meaning with spacing, boundaries, or section rhythm rather than arbitrary
   decoration.
6. Check long content, missing data, localization, narrow screens, zoom, and
   focus states so the hierarchy survives realistic conditions.
7. Verify that headings outline the page, primary and secondary actions remain
   distinguishable, and color is not the only priority signal.

## Output

Return the intended reading order, the strongest hierarchy problems, concrete
changes in priority order, and the conditions used to verify them.
